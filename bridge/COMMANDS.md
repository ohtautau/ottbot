# 聊天指令规范

模型参数支持固定编号：`/m 1` Luna、`/m 2` Sol、`/m 3` Terra、`/m 4` Astra。`/模型 2`、`/model 2`、`/m sol` 等价。菜单逐项显示编号、名称及可直接发送的完整指令；裸数字仍作为普通聊天。

解析器的唯一指令注册表是 `commands.mjs`，微信入口、任务路由和执行器共用；新增指令必须在此注册，重复别名会在启动时拒绝。

| 功能 | 中文 | 英文 | 缩写/兼容别名 |
| --- | --- | --- | --- |
| 帮助 | 帮助 | help | h、? |
| 状态 | 状态 | status | st |
| 模型 | 模型 | model | m |
| 推理 | 推理、思考 | reasoning、effort | r、re |
| 默认执行端 | 执行、执行端 | target | t、use |
| 单次服务器任务 | 服务器 | server | srv、s |
| 单次电脑任务 | 电脑、本机 | computer | pc、c |
| 清空微信上下文 | 清空、清除 | clear | cl |

每条指令必须使用 `/` 前缀，也接受全角 `／`。英文命令忽略大小写，命令和参数以空白分隔，忽略整条消息首尾空白。`/m sol`、`/模型 sol` 和 `/MODEL SOL` 等价。完整模型 ID 和任务正文保留原有大小写。

设置指令每次只接受一个参数；无参数显示菜单或当前状态。状态和清空不接受参数。`/h r`、`/help 推理`、`/帮助 model` 显示主题帮助。

默认执行端参数支持服务器的全部别名（如 `srv`、`server`、`服务器`）及电脑的全部别名（如 `pc`、`computer`、`电脑`）。`/t pc` 改变后续默认执行端，`/srv 任务内容` 只指定本次执行端。任务正文支持换行，不再次解析正文里的指令。

推理数字编号保持固定：0 默认、1 low、2 medium、3 high、4 xhigh、5 max、6 ultra；只接受当前模型支持的档位，也保留中英文参数。

未知命令、额外参数和不受支持的设置直接返回错误提示，不调用 AI，不更改已有设置。设置指令附图会被拒绝，图片任务可用 `/srv` 或 `/pc`。裸数字、正文中间的 `/` 和以 `//` 开头的文字作为普通聊天，不修改设置。当前没有隐式“回复数字即选择”的模式。

`/cl` 由微信接收端处理，只清理短期上下文；其他入口没有相同上下文时返回说明，不删除博客或微信聊天记录。

回复使用适合微信纯文本的格式：`【标题】`、空行、逐行字段、空行、下一步提示。状态只显示状态，不附整份帮助；帮助按主题分组；成功显示实际生效值和生效时点；错误显示原因、设置是否保持及正确示例。避免依赖 Markdown 表格或长段落。

示例：

```text
【设置成功】

推理强度：2 · medium（中）

下一条任务生效 · 重启保留
/r 查看编号
```

显示约定：栏目用【标签】，设置用字段与冒号，帮助菜单使用数字编号，在线/离线分别用 ✓/✗，执行路径使用 →；不同区域用 ──────── 与前后空行隔开。菜单编号仅用于阅读，选择仍需发送完整指令。
